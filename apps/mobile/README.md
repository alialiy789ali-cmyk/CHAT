# سيادي — تطبيق الجوال · Sovereign mobile

تطبيق React Native (Expo) لنظامي Android و iOS. **يتصل بنفس الخادم** الذي يستخدمه الويب —
نفس الـAPI ونفس بروتوكول الوقت الحقيقي (`packages/shared`) — بدون أي خادم وسيط.

## التشغيل

```bash
cd apps/mobile
npm install

# عنوان الخادم: على محاكي Android استخدم 10.0.2.2 (الافتراضي)،
# وعلى جهاز حقيقي استخدم عنوان جهازك في الشبكة مثل http://192.168.1.20:8787
EXPO_PUBLIC_API_URL=http://192.168.1.20:8787 npm start

# أو
npm run android      # محاكي/جهاز Android
npm run ios          # محاكي iOS (macOS فقط)
```

تأكد أن الخادم يعمل ومتاح على الشبكة:

```bash
curl http://192.168.1.20:8787/api/health     # من جهاز آخر على نفس الشبكة
```

> ملاحظة: `localhost` داخل التطبيق يشير إلى الهاتف نفسه، لا إلى جهاز التطوير — لذلك يُضبط
> العنوان صراحةً. هذا أكثر سبب شائع لفشل الاتصال.

## ما هو منفّذ فعلاً

| الشاشة | الوظائف الموصولة بالخادم |
| --- | --- |
| تسجيل الدخول | `/api/auth/login` مع TOTP، تخزين رمز التحديث في `expo-secure-store` (Keychain/Keystore)، تدوير تلقائي عند 401 |
| إنشاء حساب | `/api/auth/register` + تحقق الحقول بنفس قواعد الخادم |
| المحادثات | قائمة حقيقية مع عدّاد غير المقروء وترتيب حسب آخر رسالة، تحديث فوري عبر WebSocket، سحب للتحديث |
| المحادثة | إرسال عبر WebSocket (`message.send` + ack) مع بديل HTTP، إيصالات القراءة، تعديل/حذف يُعكسان فوراً، **طابور رسائل عند انقطاع الشبكة** يُرسل تلقائياً عند العودة |
| الموجز | `GET /api/feed`، نشر، إعجاب، متابعة، سحب للتحديث |
| الإعدادات | تحديث الملف، إعدادات الخصوصية، الجلسات وإلغاؤها، تصدير البيانات، تسجيل الخروج |

## جودة الشبكة الضعيفة (مطلب صريح)

- مؤشر اتصال ظاهر أعلى الشاشة (`ConnectionBanner`): «جارٍ الاتصال / إعادة الاتصال / غير متصل».
- إعادة اتصال تلقائية بتراجع أسّي مع عشوائية، وإعادة اشتراك في المحادثات بعد كل reconnect.
- نبضات (heartbeat) تكشف الاتصال الميت الذي لا يُغلق رسمياً — شائع عند تبديل Wi-Fi ⇄ بيانات.
- الرسائل التي تفشل تُحفظ في طابور محلي وتُرسل عند عودة الاتصال بدل الضياع.
- كل طلب شبكة يعيد خطأً مفهوماً (`network_unreachable`) بدل الفشل الصامت.

## ما هو **غير** منفّذ بعد (بصراحة)

| البند | الحالة |
| --- | --- |
| المكالمات الصوتية/المرئية | الواجهة الخلفية جاهزة (إشارات + TURN)، لكن الوسائط تحتاج `react-native-webrtc` وبناءً أصلياً (Expo Dev Client / prebuild) — لم يُضَف بعد لتجنّب تبعية أصلية غير مختبَرة |
| إشعارات الدفع | تتطلب مفاتيح FCM/APNs من المالك وخطة خادم إرسال — غير منفّذة (والتطبيق لا يدّعيها) |
| إرفاق الوسائط من الكاميرا/المعرض | الـAPI يدعمها (`POST /api/files`) ولم تُربط بعد بواجهة |
| نشر على App Store / Google Play | يتطلب حساباً مطوّراً ومراجعة — قرار المالك |
| اختبار على أجهزة حقيقية | **لم يُجرَ بعد**؛ الكود مُتحقَّق منه بالأنواع فقط (انظر أدناه) |

## حالة التحقق (لا ادعاءات)

- `npx tsc -p tsconfig.json --noEmit` — فحص الأنواع (يشمل التطابق مع عقود `packages/shared`).
- لا توجد بعد اختبارات واجهة آلية ولا جلسة اختبار على جهاز حقيقي؛ سيُسجَّل ذلك في
  `docs/feature-log.md` عند تنفيذه.
