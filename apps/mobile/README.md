# سيادي — تطبيق الجوال · Sovereign mobile

تطبيق React Native (Expo) لنظامي Android و iOS. **يتصل بنفس الخادم** الذي يستخدمه الويب —
نفس الـAPI ونفس بروتوكول الوقت الحقيقي (`packages/shared`) — بدون أي خادم وسيط.

## التشغيل

```bash
cd apps/mobile
npm install

# عنوان الخادم: على محاكي Android استخدم 10.0.2.2 (الافتراضي)،
# وعلى جهاز حقيقي استخدم عنوان جهازك في الشبكة مثل http://192.168.1.20:8787
EXPO_PUBLIC_API_URL=http://192.168.1.20:8787 npm start

# أو
npm run android      # محاكي/جهاز Android
npm run ios          # محاكي iOS (macOS فقط)
```

تأكد أن الخادم يعمل ومتاح على الشبكة:

```bash
curl http://192.168.1.20:8787/api/health     # من جهاز آخر على نفس الشبكة
```

> ملاحظة: `localhost` داخل التطبيق يشير إلى الهاتف نفسه، لا إلى جهاز التطوير — لذلك يُضبط
> العنوان صراحةً. هذا أكثر سبب شائع لفشل الاتصال.

## ما هو منفّذ فعلاً

| الشاشة | الوظائف الموصولة بالخادم |
| --- | --- |
| تسجيل الدخول | `/api/auth/login` مع TOTP، تخزين رمز التحديث في `expo-secure-store` (Keychain/Keystore)، تدوير تلقائي عند 401 |
| إنشاء حساب | `/api/auth/register` + تحقق الحقول بنفس قواعد الخادم |
| المحادثات | قائمة حقيقية مع عدّاد غير المقروء وترتيب حسب آخر رسالة، تحديث فوري عبر WebSocket، سحب للتحديث |
| المحادثة | إرسال عبر WebSocket (`message.send` + ack) مع بديل HTTP، إيصالات القراءة، تعديل/حذف يُعكسان فوراً، **طابور رسائل عند انقطاع الشبكة** يُرسل تلقائياً عند العودة |
| المحادثة المشفّرة | تشفير حقيقي بإحدى بروتوكولات Signal (`libsignal-v1`) لكل جهاز مستلم، إرسال عبر HTTP لأن كل جهاز يحتاج مغلّفه الخاص، فك التشفير عند العرض مع ذكر السبب عند الفشل، وبصمة الجهاز/رقم الأمان من نفس بنية الويب (نفس الأرقام تُقرأ من الهاتف والمتصفح) |
| الموجز | `GET /api/feed`، نشر، إعجاب، متابعة، سحب للتحديث |
| الإعدادات | تحديث الملف، إعدادات الخصوصية، الجلسات وإلغاؤها، تصدير البيانات، تسجيل الخروج |

## التشفير طرفياً على الجوال (كيف يعمل فعلاً)

- **البروتوكول**: `@privacyresearch/libsignal-protocol-typescript` — تنفيذ Signal Protocol بجافاسكربت
  خالص. لماذا لا Olm (المستخدم في الويب)؟ لأن Olm وحدة WebAssembly لا تعمل على Hermes، ولذلك
  يستخدم المتصفح `olm-v1` والهاتف `libsignal-v1`، والخادم يخزّن مغلفاً لكل جهاز مع وسم المخطط.
- **المفاتيح**: هوية واحدة لكل جهاز تُولَّد مرة وتُخزَّن في `expo-secure-store`
  (Keychain على iOS / Keystore على Android)، مع مفتاح موقّع ومجموعة مفاتيح لمرة واحدة تُنشر على الخادم.
- **العشوائية والمبادئ الأولية** (`src/lib/e2ee/runtime.ts`): كل مفاتيح الجهاز تأتي من
  `getRandomValues` الخاص بالمنصة — على الجوال من `expo-crypto` (مولّد عشوائية أصلي). المبادئ
  المتماثلة (AES/HMAC/SHA) من التنفيذ الخالص المضمّن في المكتبة لأنه لا يوجد `crypto.subtle` على
  React Native. التطبيق **يرفض** تشغيل طبقة التشفير إن لم يجد مصدر عشوائية حقيقي: لا توليد مفاتيح
  بمولّد ضعيف.
- **الحدود المعلنة**: لا يمكن لهذا العميل إنتاج مغلفات `olm-v1`، لذلك أي جهاز بمخطط آخر يُبلَّغ عنه
  في الواجهة بدل تجاهله؛ ولا تُشفَّر المرفقات بعد (تُعطَّل في المحادثات المشفّرة).

### اختبارات التشفير على الجوال

```bash
npm run test -w @sovereign/mobile        # 25 اختبار وحدة (تشفير حقيقي + تخزين + مسار الجوال)
npm run test:e2ee -w @sovereign/mobile   # 34 فحصاً مباشراً ضد خادم حقيقي على :8787
```

`test:e2ee` يستورد ملفات التطبيق نفسها (`src/lib/e2ee/*`) ويجري: تسجيل جهازين، نشر المفاتيح، بناء
جلسة من حزمة مُطالَب بها، إرسال/رد/فك تشفير، رفض ciphertext مُعدَّل، جهاز ثانٍ لنفس الحساب يستقبل
نسخته، جهاز بمخطط آخر يُبلَّغ عنه، وتطابق رقم الأمان على الجهازين. حساباته ثابتة الأسماء
(`phonelive_a`, `phonelive_b`, `phonelive_browser`) لتُعادة الاستخدام بين التشغيلات بدل استهلاك
حد التسجيل.

## جودة الشبكة الضعيفة (مطلب صريح)

- مؤشر اتصال ظاهر أعلى الشاشة (`ConnectionBanner`): «جارٍ الاتصال / إعادة الاتصال / غير متصل».
- إعادة اتصال تلقائية بتراجع أسّي مع عشوائية، وإعادة اشتراك في المحادثات بعد كل reconnect.
- نبضات (heartbeat) تكشف الاتصال الميت الذي لا يُغلق رسمياً — شائع عند تبديل Wi-Fi ⇄ بيانات.
- الرسائل التي تفشل تُحفظ في طابور محلي وتُرسل عند عودة الاتصال بدل الضياع.
- كل طلب شبكة يعيد خطأً مفهوماً (`network_unreachable`) بدل الفشل الصامت.

## ما هو **غير** منفّذ بعد (بصراحة)

| البند | الحالة |
| --- | --- |
| المكالمات الصوتية/المرئية | الواجهة الخلفية جاهزة (إشارات + TURN)، لكن الوسائط تحتاج `react-native-webrtc` وبناءً أصلياً (Expo Dev Client / prebuild) — لم يُضَف بعد لتجنّب تبعية أصلية غير مختبَرة |
| إشعارات الدفع | تتطلب مفاتيح FCM/APNs من المالك وخطة خادم إرسال — غير منفّذة (والتطبيق لا يدّعيها) |
| إرفاق الوسائط من الكاميرا/المعرض | الـAPI يدعمها (`POST /api/files`) ولم تُربط بعد بواجهة |
| نشر على App Store / Google Play | يتطلب حساباً مطوّراً ومراجعة — قرار المالك |
| اختبار على أجهزة حقيقية | **لم يُجرَ بعد**؛ لا يوجد جهاز/محاكي في بيئة التطوير هذه، والتحقق جرى باختبارات وحدة واختبار مباشر ضد خادم حقيقي (انظر أدناه) |
| شاشة التحقق من الأجهزة ورقم الأمان | المنطق جاهز (`safetyNumberWith`, `safetyEmojiWith`)، والشاشة نفسها لم تُبنَ بعد |
| نسخ الرسائل بين أجهزة المستخدم نفسه (self-sync) | الأجهزة الأخرى تُوجَّه إليها مغلفات فعلاً، لكن واجهة الجوال لا تعرض بعد رسائل أُرسلت من جهاز آخر بشكل صحيح في كل الحالات |
